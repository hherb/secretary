# Allowlist for check-public-log-hygiene.sh (#467).
#
# RULE 1: every `privacy: .public` interpolation must render through
#   `diagnosticDetail(` — counted per interpolation, not per line.
# RULE 2: no `String(describing:` / `String(reflecting:` / `.localizedDescription`
#   anywhere in the guarded scope. Fail-closed and name-blind.
# RULE 3: no bare `"\(error)"` interpolation for a conventional catch binding.
#   Best effort — a denylist by necessity, see the script header.
#
# These are the reviewed exceptions.
#
# Format, one per line:
#   <repo-relative-path><TAB><rule: 1|2|3><TAB><exact trimmed source line><TAB><reason>
#
# The match is on the EXACT source line with leading/trailing whitespace stripped —
# NOT a substring. A substring entry exempts every future line in the same file
# that happens to contain it; the entry below for BookmarkVaultLocationStore was
# demonstrably able to exempt a line rendering `err.localizedDescription` raw.
# Re-indenting an exempted line keeps the entry valid; editing its content does
# not, which is the correct price for a line that bypasses the only mechanism
# keeping secrets out of the unified log store. A short needle is therefore inert
# rather than over-broad, which the `--self-test` pins by mutation.
#
# Blank lines and `#` comments are ignored.
#
# Adding an entry is a SECURITY DECISION. Justify it in the reason field.

It calls diagnosticDetail internally, proven byte-exact by DiagnosticLogTests.testDiagnosticIsSiteAndDetailOnly and testFormatterAppliesDefaultDeny — so it IS gated, one level of indirection down.

# ---- RULE 3: reviewed bare interpolation ----

Not a log sink: this builds ON-SCREEN copy for the Unlock screen (#341 requires a non-silent message), so it never reaches the unified log store and rule 3's laundering concern does not apply.
