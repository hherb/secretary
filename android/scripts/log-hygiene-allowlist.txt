# Allowlist for check-log-hygiene.sh (#472).
#
# RULE A: any android.util.Log reference outside the sanctioned façade file.
#   Not consulted here — logging at all outside the façade is the violation,
#   not a renderable value that could be reviewed as safe. No entries exist
#   or ever will for rule A.
# RULE B1: throwable-shaped constructs (.message / .localizedMessage /
#   .stackTraceToString() / .printStackTrace()) rendering a value that may
#   carry a carried diagnostic. Fail-closed and name-blind.
# RULE B2: no .toString() anywhere in the guarded scope. Fail-closed and
#   name-blind — the name-based form was the demonstrated bypass on iOS.
# RULE C: no bare `$e` / `${e}` interpolation for a conventional catch
#   binding. Best effort — a denylist by necessity, see the script header.
#
# These are the reviewed exceptions.
#
# Format, one per line:
#   <repo-relative-path><TAB><rule: B1|B2|C><TAB><exact trimmed source line><TAB><reason>
#
# The match is on the EXACT source line with leading/trailing whitespace
# stripped — NOT a substring. A substring entry exempts every future line in
# the same file that happens to contain it, which was demonstrably
# exploitable on the iOS sibling of this guard (#467). Re-indenting an
# exempted line keeps the entry valid; editing its content does not, which is
# the correct price for a line that bypasses the only mechanism keeping
# secrets out of logcat. A short needle is therefore inert rather than
# over-broad, which the `--self-test` pins by mutation (the X1/X2 pair).
#
# Blank lines and `#` comments are ignored.
#
# Adding an entry is a SECURITY DECISION. Justify it in the reason field.
#
# Two sections:
#   SECURITY DECISIONS (rules B1, C) — a value that CAN carry a secret is
#     asserted safe to render here. Populated now. (Rule A is an absolute
#     prohibition with no allowlist entries — see above.)
#   NON-THROWABLE RECEIVERS (rule B2) — a `.toString()` call whose receiver is
#     not throwable-shaped at all (a StringBuilder, a Uri, a Long). Added in a
#     later task once the cleanup has settled which `.toString()` calls
#     survive; populating it now would be guessing at code this task does not
#     touch.
