# Allowlist for scripts/check-error-payload-hygiene.py (#474 + #480 + #486).
# There is no shell counterpart for this guard — unlike the iOS/Android
# log-hygiene guards, this one was Python from the start.
#
# THE RULE: an error payload — a `core` variant under core/src/**, an FFI
# bridge type under ffi/secretary-ffi-bridge/src/** (#480 adds this root),
# or a binding-wrapper type under ffi/secretary-ffi-py/src/** or
# ffi/secretary-ffi-uniffi/src/** (#486 adds these two) — must not carry a
# runtime String nobody has vouched for. `E1` covers interpolation in ALL
# FOUR roots; `E2`/`E3` cover declaration and construction site in the
# bridge AND the two wrapper roots; `E4` (`impl GatedDetail`) is bridge-only
# (the trait is `pub(crate)` there, so no wrapper crate can implement it);
# `E5` (`format!` confinement) is wrapper-only — see the five-rule paragraph
# below for the full definitions. These are the reviewed exceptions.
#
# Format, one per line, TAB-separated — IDENTICAL to the two shell log-hygiene
# guards' allowlists, so that scripts/lib/hygiene-allowlist.sh::allowlisted
# parses this file unchanged (core/tests/error_payload_hygiene_parity.rs
# exercises exactly that claim, rather than leaving it asserted-but-unchecked):
#
#   <repo-relative-path><TAB><rule><TAB><whole collapsed #[error(...)] attribute text — or, for E4, the impl header —><TAB><reason>
#
# This guard has FIVE rules (#474 + #480 + #486) across FOUR roots
# (core/src/**, ffi/secretary-ffi-bridge/src/**, ffi/secretary-ffi-py/src/**,
# ffi/secretary-ffi-uniffi/src/**). `E1` scans ALL FOUR roots: a
# `#[error(...)]` message must not interpolate a field whose type is not
# provably data-free. `E2`/`E3` apply to the bridge AND the two binding
# wrapper crates — their error types genuinely need prose, so instead of
# denying by TYPE they are gated by DECLARATION and CONSTRUCTION SITE: `E2`
# requires a `String` field to be declared under one of the pinned
# GATED_FIELD_NAMES; `E3` requires the expression at a gated field's
# construction site to be a literal, a `detail::*` constructor call, the
# field's own name, or (wrapper roots only) a single-hop field access
# ending in the gated name (`uuid_hex: a.uuid_hex`). `E4` requires every
# `impl GatedDetail for X` to live in
# ffi/secretary-ffi-bridge/src/error/detail.rs and name a type this guard
# itself scans — BRIDGE-ONLY, since `GatedDetail` is `pub(crate)` there and
# no wrapper crate can implement it. `E5` confines `format!` to each
# wrapper crate's own sanctioned detail.rs — WRAPPER-ONLY, since the bridge
# is deliberately excluded (most of its `format!` sites build filenames, a
# legitimate non-error use that confinement would cost ~9 allowlist entries
# to accommodate). The column exists for format parity with the shell
# guards' three/four-rule allowlists — and, now that this guard genuinely
# has five rules of its own, for the identical load-bearing reason those
# guards have it: telling readers and `allowlisted()` alike which rule a
# given entry exempts.
#
# THE KEY is the ENTIRE `#[error(...)]` attribute, not just its first source
# line: for a multi-line attribute (e.g. sync/error.rs's
# ConflictCopyScanIoFailed), keying on the first line alone would produce the
# literal key `#[error(`, which is NOT unique — a second multi-line attribute
# in the same file collides on it, so an entry reviewed to exempt ONE variant
# would silently also exempt an UNREVIEWED one. That is exactly the class of
# bug this format replaces: an earlier draft of this guard keyed on the
# attribute's first line only, and was found bypassable on exactly this
# shape before it ever shipped. The key is whitespace-collapsed to one
# line (internal runs of whitespace become a single space) so it is
# insensitive to re-wrapping and carries no TAB or newline of its own — the
# guard's `check_key_shape` self-test control asserts that property, which is
# what makes it safe for `allowlisted()`'s TAB-column split.
#
# For an `E4` row the key is NOT a `#[error(...)]` attribute at all — E4
# rows exempt an `impl GatedDetail for X` line, not a variant. The key there
# is the impl header collapsed to one line, from the `impl` keyword up to
# but EXCLUDING the opening body brace (a `where` clause or a bare `;`
# terminates it the same way — see `impl_target_text`); the impl's `{}`
# body is never part of the key, so an E4 entry's third column ends at the
# type name, with no trailing `{}`.
#
# The match is on the EXACT collapsed attribute text with leading/trailing
# whitespace additionally stripped by `allowlisted()` — NEVER a substring. A
# substring entry exempts every future occurrence of the same needle anywhere
# in the same file, which was demonstrably exploitable on both log-hygiene
# guards (#467 / #475: an entry meant for one BookmarkVaultLocationStore line
# silently exempted an unrelated later line that raw-rendered
# `err.localizedDescription`). Re-indenting an exempted line, or reflowing a
# multi-line attribute onto a different number of physical lines, keeps an
# entry valid (whitespace-collapse absorbs it); editing its message text does
# not, so a bypass line cannot be quietly repurposed to cover something else.
#
# Blank lines and `#` comments are ignored.
#
# ADDING AN ENTRY IS A SECURITY DECISION — it is a claim, made by a human
# reviewer, that no runtime value reaching this exact message can carry vault
# plaintext, a password, a mnemonic, or key bytes. Justify it in the reason
# field, and re-review whenever the entry's producers change.
#
# Sectioned by review weight, lowest first: content already disclosed by the
# threat model needs the least scrutiny; a site whose safety depends on every
# current producer staying well-behaved (something this guard structurally
# cannot verify — see its LIMITS docstring: "it sees DECLARATIONS, not
# construction sites") needs the most.
